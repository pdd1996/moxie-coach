# LeetCode 刷题技巧（转行版）

> 目标：3 个月吃透「面试经典 150 题」核心套路，应对转行算法面试。
> 不是为了成为算法竞赛选手，是为了**面试能答上来**。

---

## 一、核心心法

### 1. 刷题不是学数学，是攒"手感"
转行面试考的算法题，80% 是套路题。不需要天赋，需要**见过的题量**。
没写过 ≠ 学不会，只是还没开始。

### 2. 按"套路"分组，别按"数量"刷
双指针做 5 道，胜过随机刷 50 道。
按题型分组刷，比按难度刷、按数量刷高效得多。

### 3. 看懂 ≠ 会写
光看题解不算会。能**关掉题解默写出来**才算会。

### 4. 固定一门语言
转行推荐 **Python**（代码短、写得快）或 **JavaScript**（前端方向）。
别今天 C++ 明天 Java，切换语言是最浪费时间的。

---

## 二、每道题的标准流程（关键，别跳）

```
1. 计时 20 分钟 → 超时直接看题解，别钻牛角尖
2. 看题解后 → 关掉题解，从头默写到能跑通
3. 写一句话笔记 → "什么时候用这个套路"
4. 3 天后重做错的题 → 不复习等于白刷
5. 按主题做完再做下一个 → 别跳着刷
```

## 六、起步

**今天就做 #88**（合并两个有序数组），然后 #27、#26，把"双指针"这一类吃透。

```python
# #88 合并两个有序数组（双指针，从后往前填）
def merge(nums1, m, nums2, n):
    p = m + n - 1
    p1, p2 = m - 1, n - 1
    while p2 >= 0:
        if p1 >= 0 and nums1[p1] > nums2[p2]:
            nums1[p] = nums1[p1]
            p1 -= 1
        else:
            nums1[p] = nums2[p2]
            p2 -= 1
        p -= 1
```

## 七、目标校验

3 个月后你应该能做到：
- [ ] 看到"有序数组"立刻想到双指针
- [ ] 看到子串问题立刻想到滑动窗口
- [ ] 链表题能 5 分钟手写出 dummy 节点方案
- [ ] 二叉树题能写出递归三件套
- [ ] DP 题能 3 分钟内写出状态定义和转移方程

完成一项打一个勾。全勾了，算法轮就稳了。


这个是核心 自己想 15 分钟 → 想不出看题解 → 关掉题解默写一遍 → 隔 3 天再做一次。光看懂不算会，能默写出来才算。 



自己想 15–20 分钟 — 不自己卡一下，你的脑子不会真正"接住"这个套路；直接看题解，知识只停留在眼睛里。
想不出就看题解 — 转行不考难题怪题，超时还死磕是浪费时间，性价比最低。
关掉题解默写一遍 — 这一步是分水岭。看懂 ≠ 会写，只有关掉题解能从头写到跑通，才说明套路进了你的手，不只是进了眼。
隔 3 天再做一次 — 不复习等于白刷，艾宾浩斯遗忘曲线，3 天后还记得才变成长期记忆。
唯一的取舍是那个时间数字：我对话里说 15 分钟、文件里写 20 分钟，你按自己节奏定一个固定值就行——重点是"卡住就停，别死磕"，不是数字本身。Easy 可以 15 分钟，Medium 给 20–25 分钟。

一句话记住：能默写出来，才算会。 这条做到了，其它都是顺水推舟。



找入口三步法（通用，不只这道题）
第 1 步：先别想代码，手算一个例子
题目：合并 [1,2,3] 和 [2,5,6]。
放下笔，像小学生排座位一样手动做一遍。你会怎么排？

大概率你会这样：眼睛同时盯着两个数组的开头 1 和 2，比一下，1 小，先把 1 放下来；再看 2 和 2，一样大，放一个 2……

停。你已经做出了这道题。 你刚才用的就是"双指针"——你天然就会，只是不知道它叫这个名字。

第 2 步：观察自己刚才用了什么动作
把你手算的动作拆成机器能执行的步骤：

左手一个指针指 nums1，右手一个指针指 nums2
每次比较两边的数，把小的放下来，那边指针往后移一格
一边用完了，把另一边剩下的全放下来
这就是算法。 代码只是把这四句话翻译成语法。

第 3 步：看题目有没有"陷阱"，调整动作
88 题的陷阱是：nums1 要原地装下结果，但它前面自己也有数据。如果你从前往后放，会覆盖还没用的元素。

怎么破？问自己：nums1 有没有空位是绝对不会被碰的？ ——尾巴那 n 个 0。所以反过来，从后往前填，每个位置只填一次，永远不会覆盖有用数据



找边界三问（写完代码必做）
写完代码别急着交，主动攻击自己的代码——专门挑最容易出问题的输入喂进去。固定问三个问题：

第 1 问：指针/下标会不会越界？
凡是有下标、指针在动的代码，都问："谁会先到头？到了头我还在用它怎么办？"

88 题就是这个。三个指针 p1、p2、p，每回合都在减。问自己：

p1 减到 -1 会怎样？→ 还去读 nums1[-1]？越界。
p2 减到 -1 会怎样？→ 这正是循环该停的信号。
怎么自己逼出来：列"耗尽顺序"。两个指针都能先用完，那就有两种情况：

nums1 先完	nums2 先完
我这题会触发吗？会	会触发吗？会
我刚才让你跑 [4,5,6] 和 [1,2,3] 就是专门构造"nums1 先完"的情况——你的 bug 就藏在这。你之前的 [1,3,5] 和 [2,4,6] 恰好是 nums2 先完，所以没暴露。

经验法则：哪种顺序你手算时没走过，就专门造个例子走它。

第 2 问：空会不会出事？
任何参数是"数量"的，都试 0。88 题就是 m=0 或 n=0：

n=0（nums2 空）：循环根本不进，nums1 不动 → 对。
m=0（nums1 空）：p1 = -1，第一次就靠 p1 >= 0 挡住，全走 else 把 nums2 搬进去 → 对。
经验法则：每个"数量参数"各试一次 0，再试一次"两个都是 0 之外的最小值"（这题 m+n≥1，不用试 0,0）。

第 3 问：极端数据会不会出事？
一个全比另一个大：[7,8,9] 和 [1,2,3]（走遍 if 全放 nums1）
一个全比另一个小：[1,2,3] 和 [7,8,9]（走遍 else 全放 nums2）
两者相等情况：[2,2] 和 [2,2]（相等时走哪条？会不会乱）
经验法则：每种 if 分支，各造一个"永远只走这条分支"的例子，确认那条分支单独跑也对。
