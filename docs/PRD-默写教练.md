## 1. 产品概述

### 1.1 背景
转行求职者刷 LeetCode 的痛点不是「缺题库」——LeetCode 本身就是题库——而是**缺乏纪律和反馈闭环**：看题解时「眼睛会了」、不复习导致白刷、跳着刷导致套路建立不起来。用户在 AI 辅助刷题中已沉淀出一套验证过的方法论（见 `刷题技巧.md`），本产品把这套方法论产品化，用软件强制执行刷题流程。

### 1.2 定位
**个人刷题纪律工具 + 可选的 AI 教练**。不是又一个刷题网站，而是套在 150 题外面的一层「流程引擎」：计时卡思路 → 超时看题解 → 关掉默写 → 一句话笔记 → 3 天后重做。

### 1.3 核心理念
> **能默写出来，才算会。** 看懂 ≠ 会写，只有关掉题解能从头写到跑通，套路才算进了手。

四条铁律（软件必须强制或促进）：
1. 按**套路分组**刷，不按数量跳着刷
2. 卡住有**时间上限**（Easy 15 / Medium 25 分钟），超时看题解不死磕
3. 看完题解必须**默写**跑通才算完成
4. **间隔复习**：3 天后重做，否则等于白刷

### 1.4 目标用户
- 主用户：用户本人（转行准备算法面试，Python/JS，Windows + Chrome/Edge）
- 泛化价值：同样方法论可被其他转行者复用（二期考虑分发）

## 2. 使用场景与用户故事

**每日主场景**（工作日 1–2 题，约 40 分钟）：
> 打开软件 → 仪表盘看到「今日复习 3 题 + 建议新题 1 道」→ 先做复习题（直接进默写模式）→ 再开新题：计时器自动开始，写代码、跑示例；25 分钟没做出来 → 看题解 → 关掉，清空代码进默写模式 → 跑通用例 → 写一句话笔记「什么时候用双指针从后往前」→ 关软件。

用户故事：
- 作为用户，我打开一道没做过的题时，软件提醒我先把题面贴进来（或一键导入我现有的 md 笔记），这样题面永久本地可用。
- 作为用户，卡住时我可以点「给个提示」，AI 按三步法逐层提示但**不给我答案**，保住「自己卡一下」的价值。
- 作为用户，默写通过后，AI 用「边界三问」审我的代码并给我 3 个攻击用例，我把它们加进用例表再跑一遍。
- 作为用户，我清了浏览器缓存也不慌——所有数据在磁盘文件里，还有每日自动备份。
- 作为用户，我想看某类套路的掌握情况，仪表盘给出分组进度和热力图。

## 3. 产品原则

1. **方法论优先**：功能设计围绕四条铁律，宁缺毋滥；任何功能不得让用户绕过默写循环。
2. **数据自主**：数据是用户磁盘上的明文 JSON，可备份、可导出、不锁定。
3. **AI 可选**：不填 API key 软件功能完整；AI 是教练不是答案机（提示分层、不给答案）。
4. **离线优先**：除 AI（可选）外全程离线可用。
5. **诚实记录**：暂停默写偷看题解等行为允许，但如实记录并展示（工具不撒谎）。

### F1 题库与仪表盘（P0）
- 内置面试经典 150 题元数据：题号、标题、难度、套路、阶段、判断信号、LeetCode CN 链接。（判题入口 `entry` 不在此预填，由 F2 贴题时从 skeleton 解析存入 problem 记录，见 D1。）
- 分组维度：按用户方法论 4 阶段（①数组/字符串/双指针/滑窗/哈希 ②链表/栈/二叉树/BST ③二分/图/堆 ④DP/贪心/回溯），阶段内再按套路；「多线程」小节标记「选做」。
- 仪表盘：今日待复习队列（逾期优先）、各套路进度条、今日建议新题（按阶段顺序取第一道未做；阶段一未做完前不跨阶段建议）。
- **数据准备（独立任务，不计入功能开发工时）**：150 题元数据需先录入 `src/data/problems.json`。来源建议：题号/标题/难度/链接从 LeetCode CN「面试经典 150 题」题单整理；阶段/套路/判断信号/`entry` 按《刷题技巧.md》及人工补充。开发前置：先产出 150 题清单，未录全前 F1 验收降级为「已录入题数全展示、分组正确」。
- **验收**：已录入题全展示，分组正确；《刷题技巧.md》中已标注套路的题目映射准确（映射表作为本功能附件，见 `specs/S1-F1/套路映射.md`）。

### F2 贴题模式（P0）
- 首次打开某题 → 贴题面板：①贴题面（markdown）②贴初始代码模板（Python/JS 各一份，可选）③贴题解（可稍后补）。
- 批量导入：浏览器文件选择器多选 `面试经典150题/*.md`，按文件名题号自动匹配到题库；已含代码块的笔记按以下约定识别为 `skeleton`：`` ```python `` 代码块→`skeleton.python`，`` ```javascript ``→`skeleton.javascript`，无语言标注的第一个代码块按用户当前默认语言存入；多个同语言块取第一个。
- 示例解析：正则提取「输入：…/输出：…」自动生成测试用例草稿（支持 LeetCode CN「输入：」/英文「Input:」两种，并剥离 `变量名 =` 前缀）；不准则在用例表格手动修正（增/删/改，用例为 JSON 参数 + 期望输出）。
- **验收**：导入用户的 `88. 合并两个有序数组.md` 后，题面正确渲染、3 个示例解析为可运行用例、Python 代码块进入 `skeleton.python`。

### F3 刷题尝试流程（P0）
- 打开已贴题的题目 → 置状态 `in-progress`，计时自动开始：Easy 15 / Medium 25 / Hard 25 分钟（可配置）。
- 计时到点：界面强提醒（计时器变红 + 提示音可选），「看题解」按钮高亮；**软约束**不弹窗锁死。
- 允许暂停，暂停时长如实计入历史记录。
- 编辑器（CodeMirror）：Python / JS 切换，**每题记住上次语言并存入 `lastLang`**（打开题时默认选该语言）；「运行用例」逐条判定，显示 实际输出 vs 期望、耗时；单条超时 5 秒判失败。
- 判定方式：宽松比对（数组/对象忽略元素顺序）；**本地跑通用例 + 用户点击「自解通过」**即记为 `self-solved`（正式判定由用户去 LeetCode 提交）。`self-solved` **也进入 SRS 排期**（首间隔 3 天，复习时进默写模式，见 F6）。
- 「去 LeetCode 提交」按钮：打开题目 CN 站页；「只看题解不刷」（针对 Hard）：跳过流程直接看题解并标记 `skipped`，不排复习。
- **V1.0 兜底**：本地无题解且点「看题解」时，提示「暂无题解，请手动粘贴（V1.1 起 AI 可生成）」，不进入默写模式。
- **验收**：从打开到跑通用例全流程无刷新；暂停后历史记录含暂停时长；切语言后 `lastLang` 持久化且重开默认正确。

### F4 默写模式（P0）
- 触发：看完题解后点「进入默写」；或复习日打开待复习题直接进默写模式（此时置状态 `reviewing`，history 的 `phase` 记 `review`）。
- 行为：题解面板收起；编辑器清空、仅保留函数签名（来自 F2 的代码模板；无模板则保留用户尝试阶段的首行签名）；计时重新开始（同时长配置）。
- 防偷看：默写期间展开题解被允许，但**展开次数记录在案**并在结果页显示（诚实原则）。
- 完成：全部用例跑通后「默写通过」可点（首次→`learned`，复习→`learned` 且 `srsLevel` 升级，达顶→`mastered`）；也可点「默写失败」（比如反复写不出来），`srsLevel` 重置为 0、排 3 天后重来，状态回 `pending-review`。
- **验收**：默写模式下题解默认收起；展开次数正确记录；首次通过/复习通过/失败三种路径的状态与 SRS 排期正确更新。

### F5 一句话笔记（P0）
- 默写通过/失败后弹出，固定提示语：**「什么时候用这个套路？」**，一句话（也可多行），存入该题数据。
- 题目详情页常驻展示，复习时先看笔记再默写（笔记是「判断信号」训练的一部分）。
- **验收**：笔记随题目持久化，复习入口可见。

### F6 间隔复习 SRS（P0）
- 间隔序列默认 `3天 → 7天 → 14天 → 掌握`（可配置，存 `settings.intervalsDays: [3,7,14]`）。
- **等级字段 `srsLevel`**（0=刚通过待首复习，1=过了间隔[0]那次，…，N=过了最后一个间隔后置 `mastered`，N=intervalsDays.length）。排期规则：`nextReviewAt = 今天 + intervalsDays[srsLevel]`，通过后 `srsLevel += 1`，达到 N 置 `mastered` 且不再排期。
- 规则：**默写通过或自解通过** → `srsLevel` 升一级并排下一间隔；复习时直接进默写模式（不重看题解），通过则间隔升级，失败则 `srsLevel` 重置为 0、排 3 天后重来；掌握后不再排期（设置页可手动重置 `srsLevel` 回 0 重新刷）。
- 复习时的历史记录 `phase` 用 `review`（区别于首次默写的 `reproduce`，见 A3 / F8）。
- 队列：仪表盘「今日复习」按逾期天数排序；逾期不惩罚，照常补。
- **验收**：通过/失败后的 `nextReviewAt` 与 `srsLevel` 计算正确；`self-solved` 题出现在复习队列；跨天打开软件队列刷新正确。

### F7 AI 教练（P1，四件套，需 API key）
设置项：接口地址（默认 DeepSeek，OpenAI 兼容）、API key、模型名。key 未配置时所有 AI 入口隐藏。

| 功能 | 触发 | 规则 |
|---|---|---|
| F7.1 卡住提示 | 尝试阶段点「给个提示」 | 按「找入口三步法」分层：①引导手算一个例子 ②引导观察自己的动作规律 ③点破题目陷阱。每层可「再要一层」，**永不主动给出完整算法或代码**；连点 3 层后建议转「看题解」 |
| F7.2 边界审查 | 默写通过后 | 按「找边界三问」审代码（越界？空输入？极端数据？），输出 3 个攻击用例（JSON，一键导入用例表）；**只挑毛病不给修复代码**，修改靠自己 |
| F7.3 题解生成 | 本地无题解且点「看题解」 | 生成结构化题解：套路名/判断信号/思路（按三步法展开）/Python+JS 模板/边界处理；可保存为本地题解 |
| F7.4 错题复盘 | 默写失败后 | 对比用户代码与套路模板，指出卡点，生成一张「下次提示卡」（一句话，复习时展示在笔记上方） |

- **验收**：无 key 时四件套全部隐藏不影响主流程；F7.1 连续提示不出现完整答案。

### F8 统计（P1）
- 打卡热力图（每日做题数，GitHub 风格）。
- 套路掌握矩阵：套路 × 状态（新题/学习中/已掌握）计数。
- 指标：**默写一次通过率 = 首次 `reproduce` 即 `pass` 的题数 / 有过 `reproduce` 记录的题数**（`review` 不计入分母）；自解比例（不看题解做出来的比例）；按难度平均用时。
- **验收**：数据与 history 记录一致；`review` 与 `reproduce` 在统计中区分正确。

### F11 深色模式（P1）
- 基于 Tailwind `dark:` 前缀实现，设置页切换（亮/暗/跟随系统）。
- CodeMirror 编辑器同步切换深色主题。

### F9 数据管理（P0）
- 存储：磁盘 `data/db.json`（Vite 中间件读写，原子写入 + 1 秒防抖自动保存）。
- 自动备份：每次 `GET /api/db` 时中间件检查 `data/backups/` 中当天是否已有 `db-YYYYMMDD.json`，无则复制一份；保留最近 30 份，超出按日期最旧删除。（「每日首次」由中间件按备份文件日期判定，不依赖前端启动事件。）
- 手动：设置页一键导出/导入 db.json；「清空全部数据」需二次确认。
- **验收**：清浏览器存储后数据完好；导出→清空→导入可完整还原；当天多次刷新只产生一份备份。

### F10 GraphQL 自动拉题（P2）
- 实施时先实测 `leetcode.cn/graphql`（走本地代理）：能用则在贴题面板加「自动拉取」按钮（题面+模板+示例自动填，仍可手动修正）；不能用或结构不稳定则砍掉，不影响任何功能。

## 5. 核心流程（状态机）

```
新题 → 贴题 → [尝试: 计时+写码+跑用例]  (置 in-progress)
                 ├─ 自解通过 → SRS 排期(首间 3 天, 复习进默写)
                 ├─ 超时/主动 → [看题解] → [默写: 隐题解+空代码+重计时]
                 │                            ├─ 通过 → [一句话笔记] → SRS 排期(learned)
                 │                            └─ 失败 → [笔记(可选)] → pending-review, 3 天后重来
                 └─ Hard 只看题解 → skipped（不排期, 可手动改回 new）
复习日 → 默写重做(reviewing) → 通过(间隔升级, 达顶→mastered) / 失败(重置 3 天, 回 pending-review) → … → 掌握
```

题目状态集合：`new / in-progress / self-solved / learned(看题解后默写通过) / pending-review(默写失败待复习) / reviewing(复习中) / mastered / skipped`。
（v1.2 改名：原 `learning` → `pending-review`，消除与 `learned` 的一字母混淆。）

## 6. 数据模型（db.json 摘要）

```json
{
  "settings": {
    "ai": { "baseUrl": "", "apiKey": "", "model": "" },
    "intervalsDays": [3, 7, 14],
    "timeLimitMin": { "easy": 15, "medium": 25, "hard": 25 },
    "defaultLang": "python"
  },
  "problems": {
    "88": {
      "statement": "题面 markdown",
      "skeleton": { "python": "", "javascript": "" },
      "solution": "题解 markdown",
      "testCases": [{ "label": "示例1", "args": [], "expected": "" }],
      "entry": { "python": { "name": "merge", "callType": "function" }, "javascript": { "name": "merge", "callType": "function" } },
      "note": "什么时候用这个套路：…",
      "hintCard": "AI 下次提示卡（F7.4）",
      "status": "learned",
      "srsLevel": 1,
      "history": [{
        "ts": "", "phase": "attempt|reproduce|review",
        "outcome": "pass|fail|timeout",
        "elapsedMin": 0, "pausedMin": 0, "peekCount": 0, "lang": "python"
      }],
      "nextReviewAt": "2026-08-21",
      "lastCode": { "python": "", "javascript": "" },
      "lastLang": "python"
    }
  }
}
```

字段说明（v1.2 新增/澄清）：
- `entry`：判题入口，F2 贴题时从 skeleton 解析存入；按语言分存，每项 `{ name, callType }`，`callType` ∈ `function` | `method`（后者对应 `class Solution`）。未贴题/多线程题为空。
- `srsLevel`：SRS 当前等级，0=刚通过待首复习，N=`intervalsDays.length` 时置 `mastered`。
- `lastLang`：该题上次使用的语言，F3 打开题时默认选中。
- `settings.defaultLang`：新题/无 `lastLang` 时的默认语言。
- `history.phase`：`attempt`=尝试阶段，`reproduce`=首次默写，`review`=复习日默写（三者不可混用，F8 据此区分）。
- `status` 改名：`learning` → `pending-review`。

数据模型同步定义 TypeScript 接口（类型即文档）。

## 7. 非功能需求

- **环境**：Windows 10/11 + Chrome/Edge；Node.js ≥ 18；使用入口一条命令 `npm run dev`。
- **离线**：除 AI 与 F10 外全部功能离线可用；**Pyodide 本地打包**（随产物分发，不走 CDN），首载约 10MB，加载中有进度提示。断网首载也能跑 Python。
- **数据安全**：明文 JSON 落盘；API key 存本地文件（单机自用，接受明文，设置页注明风险）；自动+手动双重备份。
- **性能**：单题用例运行本地完成，用例 ≤ 20 条、单条 ≤ 5s；界面操作无感知保存延迟。
- **深色模式**：P1（F11），晚间刷题场景。
- **兼容性**：不要求移动端；单用户单标签页（不做并发处理）。

## 8. 技术方案概要（定稿）

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | TypeScript 全栈 | 前端 + 中间件 + Worker 统一 TS，一种语法一套工具链 |
| 前端框架 | React 18 + Vite | 标准组合 |
| 样式 | Tailwind CSS v4 | 官方 Vite 插件，`dark:` 实现深色模式 |
| 组件库 | shadcn/ui | Radix 基座 + Tailwind；CLI 将组件源码复制进 `src/components/ui/`，代码归用户所有，无升级包袱 |
| Markdown 渲染 | react-markdown | 题面/题解展示；代码高亮复用 CodeMirror 主题 |
| 编辑器 | CodeMirror 6 | TS 原生，python/javascript 语言包 |
| Python 运行 | Pyodide | npm 包自带类型，浏览器内 WebAssembly |
| JS 运行 | Web Worker | TS 可写，Vite 原生支持 |
| 存储/AI 代理 | TS 版 Vite 内嵌中间件 | `vite.config.ts` 引入 `server/` 下 TS 插件；`GET/PUT /api/db` 读写 db.json（原子写入）；`/ai-api` 代理 DeepSeek（OpenAI 兼容协议） |
| 类型检查 | `tsc --noEmit` | db.json 数据模型配 TS 接口定义 |

- 接口抽象：前端只依赖 `/api/db` 与 `/ai-api` 两个接口；未来如需练习 FastAPI，用 Python 实现同接口替换中间件即可（迁移成本约半天）。
- 题库：`src/data/problems.json` 仅元数据（无版权内容）；题面/题解一律用户自贴，本地存储不分发。
- **判题函数调用约定（D1，v1.2 修订）**：`entry` 不在 `problems.json` 静态元数据里预填，而是在 **F2 贴题时从用户粘贴的 skeleton 解析**存入 problem 记录，形如 `{ name, callType }`。判题器把 `testCases.args`（JSON 字面量字符串）`JSON.parse` 后按顺序作为参数调用入口，将返回值与 `expected` 宽松比对。两种形态：自由函数（`callType:'function'`，`def merge(...)`/`function merge(...)`/`var|const|let merge=...`，JS 用 `new Function(code+';return '+name)()` 取入口）；`class Solution` 方法（`callType:'method'`，LeetCode Python 默认模板，先 `Solution()` 实例化再调方法）。无 `entry` 的题（未贴题/多线程）禁用「运行用例」，仅留编辑器。
- **判题超时（v1.2 修订）**：单条用例 5 秒超时。不能用 `Promise.race`（用户死循环会阻塞 worker，race 赢不了）。JS：每条用例独立 worker，超时 `terminate()`；Python：Pyodide `setInterruptBuffer`（SharedArrayBuffer）触发 KeyboardInterrupt。SAB 要求 Vite dev server 配 COOP/COEP 跨源隔离头。
- **Pyodide 本地打包（D2）**：通过构建步骤把 Pyodide wheel/包内联进产物（或 vendored 到 `public/pyodide/`），不依赖 CDN，保证离线首载可用。
