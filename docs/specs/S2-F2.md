# S2-F2 — 贴题模式与 md 批量导入（P0 · 对应 PRD F2）

## 目标
首次打开某题 → 贴题面板（题面/代码模板/题解）；支持多选 `面试经典150题/*.md` 批量导入，按文件名题号匹配，代码块按约定分配 skeleton，示例正则解析为用例草稿。

## 验收标准（来自 PRD F2，v1.2 修订）
- 导入用户的 `88. 合并两个有序数组.md` 后：题面正确渲染、3 个示例解析为可运行用例、Python 代码块进入 `skeleton.python`、`entry` 解析为 `{ name:'merge', callType:'function' }`。
- 贴题面板可手动贴题面/模板/题解，用例表可增/删/改。
- 批量导入按文件名题号自动匹配到题库元数据。
- 贴 LeetCode `class Solution` 形态的 skeleton 时，`entry.callType` 解析为 `'method'`。

## 数据读写点
- 写 `problem.statement` / `skeleton` / `solution` / `testCases` / `entry`
- 导入时按题号定位 `db.problems[id]`

## 涉及文件
- `src/pages/ProblemView.tsx` — `phase === 'paste'` 面板（原型已有，接持久化）
- `src/lib/import.ts` — md 解析（题号匹配、代码块约定、示例正则、`entry` 解析）
- `src/lib/entry.ts` — 从 skeleton 解析 `entry`（新建，见实现要点）
- `src/components/TestCaseEditor.tsx` — 用例表增删改（新建，原型仅展示）

## 依赖前序 spec
S0-scaffold、S0-data-layer、S1-F1（题号→元数据匹配）

## 实现要点
- **文件名题号**：正则提取开头数字（`^(\d+)\.`）。
- **代码块约定（F-2）**：` ```python ` → `skeleton.python`，` ```javascript ` → `skeleton.javascript`，无语言标注的第一个代码块按 `settings.defaultLang` 存入；同语言多块取第一个。
- **示例正则**：兼容「输入：…/输出：…」与「Input:…/Output:…」，剥离 `变量名 =` 前缀，把每个输入变量按出现顺序解析为 `args` 元素，输出为 `expected`。解析失败则留空用例让用户手填。
- `args` / `expected` 统一存为 JSON 字面量字符串（与判题器 S0-judge 对齐：`JSON.parse` 后传参）。
- **`entry` 解析（F）**：贴题保存时，**对已粘贴的每种语言 skeleton 分别独立解析**，按语言分存为 `problem.entry = { python?: { name, callType }, javascript?: { name, callType } }`（与 PRD 第 6 节、S0-judge 一致）：
  - `class Solution:` 出现 → `callType: 'method'`，方法名取 `class Solution:` 下方第一个 `def (\w+)\(`；
  - 否则 `callType: 'function'`，按优先级匹配 `def (\w+)\(` / `function (\w+)\(` / `(?:var|const|let)\s+(\w+)\s*=\s*function` / `(?:var|const|let)\s+(\w+)\s*=\s*\(`；
  - 只贴了一种语言 → 只存对应那项，另一项缺省；
  - 解析失败（无函数定义/多线程题）→ 该语言 `entry` 项缺省，该题在该语言下禁用「运行用例」。
- 贴题面板暂存到本地 state，点「贴好了」一次性 `updateProblem`（含 `entry`）。

## 不做
- F10 GraphQL 自动拉题（P2，V2.0）。
- 不自动识别多语言代码块以外的元信息。
