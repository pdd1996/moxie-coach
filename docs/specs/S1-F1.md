# S1-F1 — 题库元数据与仪表盘（P0 · 对应 PRD F1）

## 目标
内置面试经典 150 题元数据（题号/标题/难度/套路/阶段/判断信号/LeetCode 链接），按 4 阶段分组展示；仪表盘聚合今日复习队列、各套路进度、今日建议新题。

> `entry`（判题入口函数名/形态）**不在本元数据里预填**——它在 F2 贴题时从用户粘贴的 skeleton 解析存入 problem 记录（见 S2-F2 / S0-judge）。problems.json 只放题单级元数据。

## 验收标准（来自 PRD F1，v1.2 修订）
- 已录入题全展示，分组正确（阶段内再按套路）。
- 《刷题技巧.md》已标注套路的题目映射准确（映射表见 `docs/specs/S1-F1/套路映射.md` 附件）。
- 「多线程」题标记「选做」。
- 今日建议新题按阶段顺序取第一道未做（阶段一未做完前不跨阶段）。
- 今日复习队列按逾期天数排序，逾期不惩罚。

## 数据读写点
- `src/data/problems.json` — 150 题元数据（只读种子，无版权内容）
- 读 `db.json.problems` 的 `status` / `nextReviewAt` / `srsLevel` 来聚合
- 仪表盘不写数据

## 依赖前序 spec

## 实现要点
- 元数据不含 `entry`（改由 F2 贴题时从 skeleton 解析，见 S2-F2）。多线程等无统一入口的题，贴题时也识别不出 `entry`，自然禁用运行用例。
- 仪表盘「今日复习」= `nextReviewAt <= today` 且 `status ∈ {learned, pending-review, self-solved, reviewing}` 的题，按 `today - nextReviewAt` 降序。
- 「建议新题」= 按阶段 1→4，取该阶段第一道 `status === 'new'` 的题。
- 状态徽章对应 v1.2 改名后的 `STATUS_LABEL`（`pending-review`）。
- 原型仪表盘已有「逾期 1 天」徽章、热力图占位、进度条，保留并接真数据。

## 不做
- F8 的热力图/掌握矩阵/指标是 P1（V1.1），本 spec 只做仪表盘必需的进度条与队列。
- 不内置题面/题解内容（版权）。

## 实现偏离/补充（落地时确认）

- **数据架构改为运行期合并（用户拍板）**：spec「涉及文件」未列 `store.ts`/`seed.ts`，原隐含 db.json.problems 即完整 `Problem[]`。落地时确认 db.json 只存**用户状态**（`ProblemUserState`，无 meta），`problems.json` 作只读元数据在运行期由 store 按 id 合并成 `Problem[]`。好处：元数据改了（补 pattern/signal、加方法论代表题）现有用户立刻生效，无需重置 db。代价：动了已落地的 `store.ts`（合并 + `updateProblem` 剥离 meta key 防 stale 落盘）与 `seed.ts`（`seedProblems` 从完整 `Problem[]` 瘦身为 `ProblemUserState[]`）；`middleware.ts` 不需改（`isValidDb` 仍只校验 `Array.isArray(problems)`，seed 形状自动跟随）。新增类型 `ProblemUserState`，`Problem = ProblemMeta & Omit<ProblemUserState,'testCases'> & { testCases: TestCase[] }`（合并层补默认 `[]`，故 `Problem.testCases` 仍 required）。
- **补 5 条元数据**：`problems.json` 从 151 增至 156。补 `206/704/347/78`（方法论代表题，canonical）+ `1114`（多线程，`optional:true`）。原因：seed 演示态里有这些题的用户状态，合并时缺 meta 会丢；且 `套路映射.md` 明示 206/704/347/78「可按需补入」。同时从 seed 去掉 `232/643/424` 的演示态（非方法论代表、不在 150、无演示价值）。
- **Dashboard 保留 F8 占位**：spec「不做」列热力图/指标为 P1，但「实现要点」又写「保留并接真数据」。取保守解读：保留原型仪表盘的顶部 4 统计 tile + 热力图占位（继续吃 `seedStats`/`seedHeatmap`，F8 再真实化），仅把在 scope 内的复习队列/建议新题/阶段进度/套路进度接真数据（经 `srs.ts`）。逾期徽章由写死的「逾期 1 天」改为按真实逾期天数 `逾期 N 天`。
- **`tsconfig.app.json` 加 `resolveJsonModule: true`**：store 运行期 `import problems.json`，`tsc -b` 需此 flag 才能编。
- **新增 `src/lib/srs.ts`**：spec 已列。纯函数 `reviewQueue`/`suggestedNew`/`stageProgress`/`patternStats` + `todayStr`/`overdueDays`。`todayStr` 取本地日期（非 UTC），避免把今晚 23:00 的题算到明天。
- **新增 `scripts/selftest-s1.mts`**：复刻合并 + srs 聚合，对真实 `problems.json` + `seed` 跑通：merged 156、复习队列按逾期天数降序（200 逾期 1 天居首）、建议新题=阶段一第一道 new（id 3）、`optional` 仅 1114。浏览器 UI 端到端待人工点验。
- **ProblemList 阶段内按套路分组**：spec「分组正确（阶段内再按套路）」落地为每个套路一个子标题行（`pattern · N 题`）+ 组内按题号排序；多线程题在标题后显「选做」小字 + 行 dim。
- **review 后补强（2 处）**：① `mergeProblem` 读路径同样过 `stripMeta`——计划文档「防 stale meta」原只覆盖写路径，读路径 `...user` 在 `...meta` 之后会让 db 里残留的旧形状 meta 盖回 problems.json，现两端都剥离。② `getProblem` 改为从已 memo 的 `problems` 派生 `problemsById` 取值，恢复旧 store 的稳定引用语义（避免 S3 把 `[problem]` 放进 effect/memo deps 时每次渲染重跑）；`App.tsx` 给 `ProblemView` 包 `key={id}`，切题时整组件 remount 重置 `useState`（修预存在的「88→27 带着上一题代码/笔记」bug，S3 尝试流程前必须解决）。
