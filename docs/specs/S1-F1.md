# S1-F1 — 题库元数据与仪表盘（P0 · 对应 PRD F1）

## 目标
内置面试经典 150 题元数据（题号/标题/难度/套路/阶段/判断信号/LeetCode 链接），按 4 阶段分组展示；仪表盘聚合今日复习队列、各套路进度、今日建议新题。

> `entry`（判题入口函数名/形态）**不在本元数据里预填**——它在 F2 贴题时从用户粘贴的 skeleton 解析存入 problem 记录（见 S2-F2 / S0-judge）。problems.json 只放题单级元数据。

## 验收标准（来自 PRD F1，v1.2 修订）
- 已录入题全展示，分组正确（阶段内再按套路）。
- 《刷题技巧.md》已标注套路的题目映射准确（映射表见 `docs/specs/S1-F1/套路映射.md` 附件）。
- 「多线程」题标记「选做」。
- 今日建议新题按阶段顺序取第一道未做（阶段一未做完前不跨阶段）。
- 今日复习队列按逾期天数排序，逾期不惩罚。

## 数据读写点
- `src/data/problems.json` — 150 题元数据（只读种子，无版权内容）
- 读 `db.json.problems` 的 `status` / `nextReviewAt` / `srsLevel` 来聚合
- 仪表盘不写数据

## 依赖前序 spec

## 实现要点
- 元数据不含 `entry`（改由 F2 贴题时从 skeleton 解析，见 S2-F2）。多线程等无统一入口的题，贴题时也识别不出 `entry`，自然禁用运行用例。
- 仪表盘「今日复习」= `nextReviewAt <= today` 且 `status ∈ {learned, pending-review, self-solved, reviewing}` 的题，按 `today - nextReviewAt` 降序。
- 「建议新题」= 按阶段 1→4，取该阶段第一道 `status === 'new'` 的题。
- 状态徽章对应 v1.2 改名后的 `STATUS_LABEL`（`pending-review`）。
- 原型仪表盘已有「逾期 1 天」徽章、热力图占位、进度条，保留并接真数据。

## 不做
- F8 的热力图/掌握矩阵/指标是 P1（V1.1），本 spec 只做仪表盘必需的进度条与队列。
- 不内置题面/题解内容（版权）。
