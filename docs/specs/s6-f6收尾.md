# S6-F6 收尾:「重置本题 SRS」入口

## Context

状态模型重构已合并(PR #1),`ProblemStatus` 收敛为 5 值 + `self`/`lastFail` 私有标记,SRS 排期引擎(`passSchedule`/`failSchedule`)早在 S3/S4 落地。S6-F6 验收清单里只剩**「设置页可手动重置 `srsLevel` 回 0 重新刷」**这一条没实现——给用户一个「这题我想从头重学」的逃生口:把 SRS 排期与自解徽章清空、打回未开始,但题面/模板/题解/用例/笔记/历史保留(重学 ≠ 抹除历史)。

重构 spec [§6.8](../../Desktop/toAgent/moxie-coach/docs/specs/状态模型重构.md#L316) 已约定新模型下的写法。本计划落实它,并修一处 spec 与排期引擎对不上的语义 bug。

## 入口位置:ProblemView 题头(偏离 spec 原文)

S6-F6 spec 原文写「设置页加入口」,但「重置*本题*」是单题动作,放全局设置页要加题号选择器、且得离开当前题才能操作,UX 不顺。放 [ProblemView.tsx](../../Desktop/toAgent/moxie-coach/src/pages/ProblemView.tsx) 题头(挨着已有的「编辑题目」ghost 按钮、低显眼、带确认弹窗)更自然——用户正看着这题,「想重学」就在眼前发生。

可见性:`canReset` 门控下显示 —— `canEdit`(phase ∈ `attempt`/`solution`/`done`)或 `phase === 'reproduce'`,且仅当 `problem.status !== 'new'`(有东西可重置)。**重置按钮在默写阶段(`reproduce`)也放开**(R8),与「编辑题目」解耦:reset 不回贴题面板、不露题解,误触由确认弹窗挡住;而 `editProblem` 仍在 reproduce 隐藏(它会回贴题面板泄露题解)。放开 reproduce 态重置的痛点:原先到期复习题要重置得先「默写失败」混进 done 屏,那次假失败会写进 history、置 `lastFail` 再被 reset 清掉——为够到重置被迫污染历史。贴题阶段(`paste`)本就无 SRS 可重置,自然不显。

## 一处语义修正:`srsLevel` 应清 `undefined`,不是 `0`

spec(S6-F6 与重构 §6.8)都写「`srsLevel=0`」,但与排期引擎对不上:

- `passSchedule`([srs.ts:108](../../Desktop/toAgent/moxie-coach/src/pages/../../Desktop/toAgent/moxie-coach/src/lib/srs.ts#L108)):`newLevel = (currentSrsLevel ?? -1) + 1`。
  - `srsLevel=undefined`(未触碰)→ 首次通过得 level 0,排 `+intervalsDays[0]`(+3 天)。✅
  - `srsLevel=0` → 首次通过得 level 1,排 `+intervalsDays[1]`(+7 天)——**跳过了 +3 天的首复习**。
- `srsLevel` 语义注释([srs.ts:84](../../Desktop/toAgent/moxie-coach/src/lib/srs.ts#L84)):「0=刚通过待首复习」,不是「未触碰」。`status='new'` + `srsLevel=0` 自相矛盾(未碰过 vs 刚通过)。

故重置应清 `srsLevel: undefined`,真正打回未触碰形状(与 `mergeProblem` 给未触碰题补的默认一致),下次通过从 +3 天首复习走起。`lastFail`/`self` 同理清 `undefined`(渲染处都是 falsy 判定,`undefined` 与 `false` 等价,但 `undefined` 在 JSON 序列化时字段直接消失,db 更干净)。

## 改动

### 1. `src/pages/ProblemView.tsx`

**新增重置处理函数**(挨着 `skipProblem`/`editProblem` 一带):

```ts
// 重置本题 SRS(重构 spec §6.8 + S6-F6):打回未开始重学。
// 题面/模板/题解/用例/笔记/历史/lastLang 保留(重学≠抹除历史);
// SRS 排期、自解徽章、挂科标清空。srsLevel 清 undefined 而非 0——passSchedule 里
// (level ?? -1)+1:undefined → 首通过得 0 排 +3 天;0 → 得 1 排 +7 天,会跳过首复习。
// 重置后跳回题单而非就地进 attempt:落地刷题流会被「attempt 置 in-progress」effect
// 立刻翻成进行中,'未开始' 就白打了;回列表让 status=new 真正落库,用户自己点开重学。
const resetSrs = () => {
  updateProblem(problem.id, {
    status: 'new',
    srsLevel: undefined,
    nextReviewAt: undefined,
    self: undefined,
    lastFail: undefined,
  })
  setResetOpen(false)
  navigate('/problems')
}
```

> `updateProblem` 是浅合并([store.ts:203](../../src/lib/store.tsx#L203)),传 `undefined` 会覆盖旧值清字段——与 `skipProblem` 清 `nextReviewAt` 同款写法。`undefined` 经 `JSON.stringify` 序列化时字段消失,db 落盘干净。
>
> **行为修正(审 spec 时定):** 重置后**跳回题单**,不就地进 attempt。原方案「就地回 attempt」会被 [ProblemView.tsx:114-120](../../src/pages/ProblemView.tsx#L114-L120) 的「进 attempt 置 in-progress」effect 立刻翻成进行中,`status=new` 无法落库、「打回未开始」不兑现,且从 done/solution 重置与从 attempt 重置结果不一致。跳回列表:db 稳定 `new`、题单肉眼可见「未开始」+⭐消失、行为各阶段一致;代价是多一次点击重进。

**题头加按钮**(在 [ProblemView.tsx:481-485](../../Desktop/toAgent/moxie-coach/src/pages/ProblemView.tsx#L481-L485)「编辑题目」按钮旁):

```tsx
{canReset && (
  <Button variant="ghost" size="sm" onClick={() => setResetOpen(true)} title="清空 SRS 排期与自解徽章，打回未开始重学">
    <RotateCcw className="size-3.5" /> 重置重学
  </Button>
)}
```

(`RotateCcw` 从 `lucide-react` 引入,与现有图标同导入区。)

**新增确认弹窗**(挨着现有 `Dialog` 一带,复用已引入的 `Dialog`/`DialogContent`/`DialogHeader`/`DialogTitle`/`DialogFooter`):

```tsx
<Dialog open={resetOpen} onOpenChange={setResetOpen}>
  <DialogContent className="max-w-md">
    <DialogHeader>
      <DialogTitle>重置本题,从头重学?</DialogTitle>
    </DialogHeader>
    <p className="text-sm text-muted-foreground">
      会清空 SRS 排期、自解徽章 ⭐、易错标,把题打回<strong>未开始</strong>。
      题面 / 模板 / 题解 / 用例 / 笔记 / 历史记录都保留——重学不是抹除过去。
      重置后会回到题单,你随时可以点开重新开始。
    </p>
    <DialogFooter>
      <Button variant="ghost" onClick={() => setResetOpen(false)}>取消</Button>
      <Button variant="destructive" onClick={resetSrs}>重置</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

**新增 state**(挨着其他 `useState`):`const [resetOpen, setResetOpen] = useState(false)`

## 验证

`cd moxie-coach && npm run dev`,逐条对 db.json(`data/db.json`)核对:

1. **重置一题复习中的题**:打开一道 `status=learned` + `nextReviewAt<=今天`(在复习队列里)的题 → 题头点「重置重学」→ 确认 → **跳回题单,该题显示「未开始」、⭐/易错标消失**。db 该题:`status=new`、`srsLevel` 字段消失、`nextReviewAt` 消失、`self`/`lastFail` 消失;`history`/`note`/`statement`/`skeleton`/`solution`/`testCases` 保留。仪表盘复习队列不再含此题;「建议新题」可能变成它。
2. **自解题重置撤徽章**:一道 `self=true` 的题 → 重置 → db 无 `self`,题单/题头自解星消失。
3. **易错题重置清 lastFail**:`lastFail=true` 的题 → 重置 → db 无 `lastFail`,「易错」标消失。
4. **重学后首复习走 +3 天**:重置后重新点开自解通过 → db `srsLevel=0`、`nextReviewAt=今天+3`、`self=true`(没跳到 +7,验证 `srsLevel=undefined` 修正生效)。对比:若写成 `srsLevel=0` 会得 +7,即 bug。
5. **mastered 题重置**:一道 `mastered` 题 → 重置 → `status=new`、`nextReviewAt` 消失,重新进「建议新题」。
6. **默写态可重置、不误触**(R8):到期题落 reproduce 态时题头**有**「重置重学」按钮(放开 reproduce 态重置),但**无**「编辑题目」按钮(避免借机看题解);点「重置重学」走确认弹窗,取消不落库。未开始(`new`)题也不显重置按钮(无东西可重置)。
7. **取消不落库**:点「重置重学」→ 弹窗点「取消」→ db 无任何变化。
8. **dev server 运行时改库的坑**(来自重构验证记忆):改 `data/db.json` 后必须立刻刷页面再进题,否则 app 内存旧状态触发 debounce PUT 会冲掉磁盘编辑。
