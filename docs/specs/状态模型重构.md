# 状态模型重构 —— 把「荣誉 / 动作 / 排期」从一维枚举里拆开

> 独立重构步骤,**不混进 F4/F5**。F4/F5 收尾发布后再动。
> 目标:消灭 `self-solved` / `pending-review` / `reviewing` 三个混装状态,把一个 `status` 字段拆成「真状态(5)+ 自解徽章(self)+ 上轮挂科(lastFail)」,让用户面对的 5 个状态正交、让代码不再有为「荣誉」特设的例外分支。

---

## 1. 动机(这轮测试已付过代价)

当前 `ProblemStatus`([types.ts:8-16](../../src/lib/types.ts#L8-L16))一个枚举同时塞了三个维度:

| 维度 | 性质 | 里面的值 | 是「这题现在在哪」吗 |
| --- | --- | --- | --- |
| 荣誉/历史 | 怎么会的 | `self-solved` | ❌ 过去的事 |
| 当前动作 | 我在干嘛 | `in-progress`、`reviewing` | ⚠️ 动作被持久化 |
| SRS 排期 | 它到哪了 | `new`、`learned`、`pending-review`、`mastered`、`skipped` | ✅ |

已爆的 bug / 已写的特例,都是维度混装的直接症状:

- [ProblemView.tsx:130-141](../../src/pages/ProblemView.tsx#L130-L141) 的复习 effect 不得不写 `!== 'reviewing' && !== 'self-solved'`——为保「自解荣誉」特设一个例外,正是模型被荣誉维度污染的证据。
- [ProblemView.tsx:64-66](../../src/pages/ProblemView.tsx#L64-L66) 的 `entryWasSelfSolved` mount 快照 + [ProblemView.tsx:266-268](../../src/pages/ProblemView.tsx#L266-L268) 的 `entryWasSelfSolved ? 'self-solved' : 'learned'` 三元——纯粹是为了在一维枚举里区分「自解复习通过」与「失败后重写通过」。
- `reviewing` 被持久化:进复习后离开页面不结算,它会永远卡在 db 里(没人知道「进行到哪」)。
- `pending-review` 名字与语义相反:名字读作「等复习」(成功者也等复习),语义却是「上次挂科了」。
- F8 自解比例要按 `status === 'self-solved'` 算——在「荣誉占着状态位」的模型上加统计,必然再爆同类 bug。

## 2. 目标形态

### 2.1 `status` —— 真状态,5 个(回答「这题现在在哪」)

```
new          未开始(未做过)
in-progress  进行中(已开未结算,首次 attempt 置)
learned      待复习(SRS 排期中,含「刚通过待首复习 / 循环中 / 上轮挂科待重做」三种细态,由 srsLevel + lastFail 区分,不再拆成不同 status)
mastered     过关了(SRS 走完,不再排期)
skipped      没招了(只看题解不刷,不排期)
```

移除:`self-solved`、`pending-review`、`reviewing`。

### 2.2 私有标记(不作为状态展示给用户)

| 字段 | 类型 | 语义 | 顶替谁 |
| --- | --- | --- | --- |
| `self` | `boolean` | 自解徽章:首次 attempt 通过且**没看过题解**时置 `true` | 顶掉 `self-solved` 状态 |
| `lastFail` | `boolean` | 上轮复习/默写挂科 | 顶掉 `pending-review` 状态 |
| ~~reviewing~~ | — | 不持久化 | 复习中 = 会话态,离开页面即回到 `learned` |

「自解」从**状态**降级为**题单上的一颗星(徽章)**;之前拍板的「自解复习保持自解」自然变成「徽章一直亮」——不再需要 `!== 'self-solved'` 那个特例。

两条轴正交:自解题也能「过关了」(`self=true` + `mastered`),看题解解题也能「过关了」(`self=false` + `mastered`)。

### 3.1 用户可见词表(终审)

**验收标准:第一次见到的人,不解释就懂;不过的词换掉,不保留。**

**状态列(题单 / 题头 badge):**

| 机器字段 | 用户看到 | tooltip / 说明 |
| --- | --- | --- |
| `new` | **未开始** | — |
| `in-progress` | **进行中** | 开过、还没通过 |
| `learned` | **待复习** | 过了,到点还要默写;三种细态(刚通过 / 循环中 / 上轮挂科)都「待复习」,名字与语义终于对齐 |
| `mastered` | **过关了** | 间隔走完,不再排期复习 |
| `skipped` | **没招了** | 看了题解没刷,再刷随时回来 |

**徽章(不占状态列主词):**

| 机器字段 | 用户看到 | tooltip |
| --- | --- | --- |
| `self` | ⭐ | **我顺极了 —— 没看题解自己解出来的**(历史荣誉,§8 定稿:不因后续失败撤销) |
| `lastFail` | **易错** | 上次没默过 |

**按钮 / done 屏 / 统计:**

| 位置 | 原词 | 改为 |
| --- | --- | --- |
| attempt 按钮 | 自解通过 | **没看题解,直接过了** |
| done 屏(自解) | 自解通过,没看题解就拿下 | 标题 **我顺极了!** / 副文 没看题解就拿下;**不显示**「已排期 X 复习」——庆祝干净,排期在 db 静默跑、到期自然进队列催你(默写 done 屏照旧带「已排期 X 复习」,因为那种该提醒复验) |
| done 屏(达顶) | 间隔走完,已掌握 | **间隔走完,过关了** —— 不再排期复习 |
| 统计卡 | 自解比例 | **独立解出率** |
| 不动 | 默写通过率 / 默写重做 / 默写失败 / 累计完成 / 建议新题 | 已是人话,零改动 |

**难度梯度(自查):** 未开始/进行中(未知)→ 待复习(相对易)→ 过关了(系统认为稳)→ 没招了(放弃);⭐ = 相对最易、易错 = 相对最难。用户扫一眼状态列就是「我拿不拿得下」的梯度,无互相矛盾的难度暗示。

### 3.2 覆盖性:用户处境 → 落点(够用性的真证据)

不是「状态机有 5 个状态所以 5 个词」(那是循环——状态机有 5 个是因为我们定义成 5 个)。真证据是把用户从拿到题到毕业的每一步走一遍看落点,再看哪些不同处境被折叠进同一个词、为什么。

**用户处境 → 落点:**

| 用户处境 | 落到 |
| --- | --- |
| 没碰过 | 未开始 |
| 点开开始做 | 进行中 |
| 做一半离开 | 进行中 |
| 没看题解做出来 | 待复习 + ⭐ |
| 看题解(还没默写) | 进行中 |
| 看完默写出来 | 待复习 |
| 默写没写出来 | 待复习 + 易错 |
| 到点复习通过 | 待复习 |
| 到点复习挂了 | 待复习 + 易错 |
| 复习循环走完 | 过关了 |
| 看题解直接不刷 | 没招了 |
| 没招了又想刷 | 进行中 |
| 过关了再做又挂 | 待复习 + 易错 |
| 过关了再做又过 | 过关了 |
| 复习中途离开没结算 | 待复习 |
| 手动重置 | 未开始 |

每条都落进 7 个词之一。代码里所有写 `status` 的地方就这几个落点(已删 reviewing/pending-review/self-solved 的写入),机器产不出第 8 种。

**折叠点(差点加词、最后不加的决策):**

| 用户处境 | 折进 | 取舍 |
| --- | --- | --- |
| 看了题解、还没默写 | 进行中 | 页面内中间态,离开退回,不入列 |
| 复习中途离开没结算 | 待复习 | 旧模型卡「复习中」;新模型靠 `nextReviewAt` 下次继续——reviewing 降级的收益 |
| 刚通过 vs 循环中 vs 上轮挂科 | 全部「待复习」 | 用户面不需三种细态,`srsLevel`/易错内部区分,队列催时自然知道 |
| skipped 之后再自解 | ⭐我顺极了 | 历史看过题解、这轮没看;荣誉轴与排期轴分开后可接受(选 A 的代价) |
| 过关了之后又忘了 | 待复习 + 易错 | 系统不吹永久,重做失败会退化 |
| 永久跳过 vs 暂时跳过 | 合并「没招了」 | 历史能区分,增量价值低 |
| "我早就会,不想刷" | 不提供词 | 工具不撒谎,自解 30 秒能真过 |

七条折叠立得住,「够用」才立得住——它面对用户真实处境,不是我们自己定义的状态。

**一处已知折中:** ⭐「我顺极了」在「自解了但特别费劲」的题上略不诚实("顺"暗示轻松,但你可能啃了很久);tooltip 后半句「没看题解自己解出来的」补了事实。这是选情绪词的代价,接受。

## 4. 语义映射表(旧 → 新)

| 旧 status | 新 status | `self` | `lastFail` | 备注 |
| --- | --- | --- | --- | --- |
| `new` | `new` | – | – | |
| `in-progress` | `in-progress` | – | – | |
| `self-solved` | `learned` 或 `mastered` | `true` | `false` | 见下注①:达顶判 mastered |
| `learned` | `learned` | – | `false` | |
| `pending-review` | `learned` | – | `true` | 上轮挂科折进 lastFail |
| `reviewing` | `learned` | – | `false` | 复习中是会话态,迁移时无法恢复原 lastFail,按 `false` 兜底(见下注②) |
| `mastered` | `mastered` | – | – | |
| `skipped` | `skipped` | – | – | |

注①:`self-solved` 在旧模型有「达顶卡在 self-solved」的历史 bug(已在 F4 附带修复里加 `sched.mastered ? 'mastered'`)。迁移时对 `self-solved` 记录:`srsLevel >= intervalsDays.length` → `mastered`(+ 清 `nextReviewAt`),否则 `learned`;两者都 `self=true`、保留 `nextReviewAt`(mastered 除外)。

注②:`reviewing` 是会话态,旧库里残留的 `reviewing` 必然是「进复习后没结算就离开」的脏数据,迁移成 `learned` 且保留其 `nextReviewAt`(仍在复习队列),`lastFail` 不可恢复按 `false`。这正是「reviewing 不该持久化」要消灭的那整类边缘数据。

## 5. 行为映射(每条代码路径)

### 5.1 `selfSolved()`([ProblemView.tsx:309-321](../../src/pages/ProblemView.tsx#L309-L321))—— attempt 自解通过

```diff

-  status: sched.mastered ? 'mastered' : 'self-solved',
+  status: sched.mastered ? 'mastered' : 'learned',
+  self: true,            // 徽章:首次自解,置位
+  lastFail: false,

-  ...(sched.nextReviewAt ? { nextReviewAt: sched.nextReviewAt } : {}),
+  nextReviewAt: sched.nextReviewAt,  // 达顶时为 undefined → 显式清旧排期;非达顶排下次复习
```

> 顺带修一条 pre-existing 脏数据:旧的条件展开 `...(x ? {x} : {})` 在达顶时不写 `nextReviewAt`,浅合并会**保留**旧的排期日期(mastered 却带 stale nextReviewAt)。改直赋 `nextReviewAt: sched.nextReviewAt`,达顶传 `undefined` 显式清掉。用户不可见(mastered 本就不进复习队列),但 db 干净、与迁移 §7.1「mastered 清排期」对齐。`onReproducePass` 同改(§5.2);`onReproduceFail` 本就是直赋,无需动。

### 5.4 attempt → in-progress([ProblemView.tsx:119-124](../../src/pages/ProblemView.tsx#L119-L124))—— 不变

`new → in-progress` 逻辑保持。正名:`in-progress` 是「已开未结算」的**当前位置**(区别于 `new` 的「没碰过」),非瞬时动作,故保留持久化;`reviewing` 是纯瞬时复习动作,故降级会话态——两者不同质(§8 Q2 已定)。

### 5.5 复习入口 reviewing effect([ProblemView.tsx:130-141](../../src/pages/ProblemView.tsx#L130-L141))—— **整段删除**

不再持久化 `reviewing`。「正在复习这题」若需 UI 提示,用会话态(已有 `reproducePhaseTag === 'review'` 可用,见 [ProblemView.tsx:56-58](../../src/pages/ProblemView.tsx#L56-L58))。删除此 effect 同时消灭「暂停/恢复后 status 丢失」那整类边缘 case——这是本重构最大的代码简化。

### 5.6 `skipProblem()`([ProblemView.tsx:339-343](../../src/pages/ProblemView.tsx#L339-L343))—— 不变

`status: 'skipped'` + 清 `nextReviewAt`。

## 7. 数据迁移(`src/lib/store.tsx`)

现有 db.json 已有真实 `self-solved`/`mastered`/`learned`/`pending-review`/`reviewing` 记录,必须无损迁移。

### 7.1 迁移函数(纯函数,放 `srs.ts` 或 `types.ts` 旁)

```ts
/** 旧 status → 新形状,幂等:已是新形状则原样返回。
 *  前置:intervalsDays 非空(种子 seedSettings.intervalsDays=[3,7,14] 保证);
 *  若为空,top=0 会使所有 self-solved 误判 mastered,故调用方须保证非空。 */
export function migrateUserState(
  u: ProblemUserState,
  intervalsDays: number[],
): ProblemUserState {
  const top = intervalsDays.length
  let status = u.status
  let self = u.self ?? false
  let lastFail = u.lastFail ?? false
  switch (u.status) {
    case 'self-solved':
      status = (u.srsLevel ?? 0) >= top ? 'mastered' : 'learned'
      self = true; lastFail = false
      break
    case 'pending-review':
      status = 'learned'; lastFail = true
      break
    case 'reviewing':
      status = 'learned'; lastFail = false
      break
    // new / in-progress / learned / mastered / skipped:已新形状,不动
    default: break
  }
  // mastered 必须清排期(旧 self-solved 达顶可能残留 nextReviewAt)
  const nextReviewAt = status === 'mastered' ? undefined : u.nextReviewAt
  return { ...u, status, self, lastFail, nextReviewAt }
}
```

幂等性:迁移后 status ∈ 5 值,再跑 switch 走 default,无变化。旧备份重新加载会再迁移一次,结果相同。

### 7.2 落地点:加载即迁移 + 顺手持久化

在 store 的 `useEffect` 拉取分支([store.tsx:124-147](../../src/lib/store.tsx#L124-L147))里,`setUserById` 前对每条跑 `migrateUserState(u, db.settings.intervalsDays)`:

```ts
const map: Record<string, ProblemUserState> = {}
for (const p of db.problems ?? []) map[String(p.id)] = migrateUserState(p, db.settings.intervalsDays)
setUserById(map)
```

迁移是向前兼容:旧字段(`self-solved` 等)从 db 读进来即被替换,新字段(`self`/`lastFail`)随之写入。为让 db.json 也落成新形状(而非只在内存),加载后若发生过迁移,**触发一次 `scheduleSave()`** 把整库 PUT 回去——后续备份即新形状。判定「是否迁移过」:比较迁移前后是否有任何记录变化,有则 `scheduleSave()`。

> 不在 server 侧(`middleware.ts`)做迁移:迁移需要 `intervalsDays`(属 settings,前端领域),且 server 只校验 JSON 合法性、不解释语义。迁移留在前端,职责清晰。

### 7.3 回滚

- 迁移幂等 + 向前兼容,无需回滚脚本。
- 若新模型出问题:git revert 代码后,旧代码读到新形状 db(`learned` + `self`/`lastFail`)也能跑——`self`/`lastFail` 是旧代码忽略的额外字段;但**旧 `self-solved`/`pending-review`/`reviewing` 已被改写**,旧代码会把这些题当 `learned`(因 status 已变),功能上少了自解/挂科展示,不崩。故回滚安全但会丢「自解/挂科」的旧状态展示——这是单向迁移的代价,可接受(且每日备份仍在 `data/backups/`,最坏手动恢复)。

## 8. 语义变更 vs F4/F5 —— **需你 sign-off 的关键决策**

重构把「荣誉」从状态里抽出来,必然改变一处已验证行为,这是风险最高点,必须用 F4/F5 的 Test A/B 清单再跑一遍。

### 决策:`self` 徽章是否在复习失败后撤销?

**现状(F4/F5 已验证)**:自解题复习失败 → `status` 离开 `self-solved` → 此后再通过不再回 self-solved(「失败即降级,不再恢复」)。即自解荣誉会因一次复习失败而**永久丢失**。

**选项 A(推荐,契合本重构动机)**:`self` 是**历史荣誉,一旦获得永不撤销**。复习失败的代价完全由 SRS 承担(`srsLevel→0`、重新排期),与徽章正交。
- 理由:自解 = 「首次没看题解就拿下」,这是一次性历史事实,不会因后来忘了而变成「当初看了题解」。荣誉轴与排期轴本就该独立——这正是 §1 要消灭的混装。
- 「失败即降级」在新模型里**自然消解**:没有 `self-solved` 状态可降,也就没有「不再恢复」可言;徽章始终亮,降级体现在 SRS 重排。
- 副作用:题单上一题永远带自解星,即便后来复习挂过。**这是正交模型的应有之意**,但要在 UI 上让用户理解「星 = 当初自解过,不代表现在掌握度」(现掌握度由 status + srsLevel 表达)。

**选项 B(保留旧语义)**:复习失败时清 `self=false`,通过后不再置回。则 `self` 退化为「当前仍是自解 standing」,与「荣誉/历史」定位矛盾,且重新引入「失败要清徽章」的特例分支——又把刚拆掉的维度混装塞回去。不推荐。

> **已定稿:按 A。** §3.1 徽章「我顺极了」定性地是「历史荣誉,不撤销」——与徽章文案一致(过去时陈述「没看题解自己解出来的」,不是当前能力断言)。B 如需再议:§5.3 `onReproduceFail` 加 `self: false`、§5.2 通过时不重置 `self`,并文档化「徽章可被撤销」。

### 其余已验证行为:无变更(逐条对照)

| F4/F5 已验证行为 | 新模型下 | 变更? |
| --- | --- | --- |
| 复习通过保持自解 | 通过→`learned`(达顶 `mastered`),徽章 `self` 不变(选 A) | 展示从「状态=自解」变「徽章+状态=待复习」,语义保持 |
| 失败即降级、不再恢复 | 失败→`learned`+`lastFail`,`self` 保留(选 A);降级体现在 SRS 重排 | 语义从「撤荣誉」变「重排期」,见上决策 |
| 复习先看笔记、直进默写 | 不变(reproducePhaseTag='review' 仍会话态驱动) | 无 |
| mastered 到顶不排期 | 不变(`status='mastered'`、清 `nextReviewAt`) | 无 |
| 笔记弹窗为必经步、不二次结算 | 不变(`settledRef` 守卫不动) | 无 |
| 自解通过达顶判 mastered | `selfSolved()` `sched.mastered ? 'mastered' : 'learned'` + `self=true` | 无 |
| 题单/仪表盘笔记图标 | 不变 | 无 |

### reviewing 不再持久化带来的行为变化

- 旧:进复习后离开页面不结算 → `reviewing` 卡在 db 永远不动(已知 wart)。
- 新:离开即回到 `learned`,`nextReviewAt<=today` 仍成立 → 仍在复习队列,下次进继续直进默写。**这是修复,不是回归**。需在验证清单里确认「复习中途离开再回来,仍直进默写、不重复结算」。

### 待 sign-off 的开放问题(审 spec 时定)

**Q1:`lastFail` 的消费者 —— 已定 (a)。** `lastFail` 定性为「`history` 尾部的缓存」(最近一次 reproduce/review 的结果),`history` 是过去事实的唯一真相源;每次 pass/fail 维护它与历史尾部一致。UI 出口 = 题单/复习队列「易错」标(§3.1),并供 F8 易错率统计。遗留 `pending-review`(空 history)靠迁移置 `lastFail=true` 保住挂科信号——这是保留该冗余字段的唯一理由(§7.1)。

**Q2:`in-progress` 双重标准 —— 已定:保留「进行中」。** 定位为「已开未结算」的当前位置(区别于 `未开始` 的「没碰过」),非瞬时动作;`reviewing` 是纯瞬时复习动作故降级会话态,两者不同质。§3.1 词表已按此定稿。

**§8 的 self 徽章决策 —— 已定 A,见上。**
